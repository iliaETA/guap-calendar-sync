# GUAP Calendar Sync

Сервис следит за расписанием группы ГУАП, валидирует результат парсинга, сообщает об изменениях в Telegram, собирает подписной iCalendar-файл и синхронизирует редактируемый календарь Mail.ru через CalDAV.

Текущее расписание: [группа 8423к (`gr=7147`)](https://guap.ru/rasp?gr=7147).

## Как это работает

1. GitHub Actions раз в 30 минут скачивает расширенную страницу расписания.
2. Парсер нормализует пробелы, аудитории, преподавателей и верхнюю/нижнюю неделю.
3. Валидатор не позволяет пустому или повреждённому результату затереть рабочее расписание.
4. Новая версия сравнивается с предыдущей. Изменения отправляются в Telegram.
5. `docs/calendar.ics` пересобирается с реальными датами пар и явно разворачивается через GitHub Pages.
6. Если настроен Mail CalDAV, пары создаются в отдельном календаре `ГУАП`. Ручные изменения и удаления пользователя не перезаписываются.

`upper` соответствует верхней (нечётной) неделе, `lower` — нижней (чётной), `every` — каждой неделе. Граница недели задаётся именно понедельником, чтобы смена чётности не происходила посреди недели.

## Локальный запуск

Нужен Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m src.main
```

Проверка:

```bash
python -m unittest discover -v
```

На первом запуске старый снимок будет заменён текущим. Без Telegram-переменных синхронизация и генерация календаря всё равно работают, отправка уведомления просто пропускается.

## Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Напишите боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите `message.chat.id`.
4. Для локального запуска заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`.
5. Для GitHub Actions добавьте значения в **Settings → Secrets and variables → Actions → New repository secret** с теми же именами.

Токен нельзя коммитить в репозиторий.

## Редактируемый календарь Mail.ru

Используйте отдельный технический Mail-аккаунт и отдельный календарь `ГУАП`. Предоставьте рабочему аккаунту доступ к этому календарю с правом редактирования. В техническом аккаунте создайте пароль внешнего приложения: **Настройки → Все настройки → Безопасность → Пароли для внешних приложений**.

Добавьте в GitHub Actions два repository secret:

```text
MAIL_CALDAV_USERNAME       полный адрес технического Mail-аккаунта
MAIL_CALDAV_APP_PASSWORD   пароль внешнего приложения
```

Дополнительные параметры имеют безопасные значения по умолчанию:

```dotenv
MAIL_CALDAV_URL=https://calendar.mail.ru/
MAIL_CALENDAR_NAME=ГУАП
```

Если календарь называется не `ГУАП`, создайте в GitHub Actions repository variable `MAIL_CALENDAR_NAME` с его точным именем. Это не секрет.

Синхронизатор изменяет только события со своей служебной меткой. Посторонние события в календаре он игнорирует.

- нетронутая пара обновляется при изменении расписания ГУАП;
- вручную изменённая пара получает статус `manual_override` и сохраняется как есть;
- вручную удалённая пара получает локальную отметку `deleted_by_user` и не создаётся снова;
- вручную изменённая пара не удаляется автоматически, даже если исчезла из расписания, и получает статус `orphaned_manual`.

Состояние хранится в `data/caldav_state.json`. Там находятся только UID, статусы и хеши; логины, пароли и содержимое рабочих событий не сохраняются.

## Автоматический календарь

Один раз откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Workflow сам загрузит содержимое `/docs` и развернёт его в Pages после каждой синхронизации.

Если шаг `Configure GitHub Pages` возвращает `Get Pages site failed: Not Found`, значит Pages ещё не включён или в поле **Source** выбран другой способ публикации. Выберите **GitHub Actions**, сохраните настройку и повторно запустите workflow.

Ссылка подписки будет такой:

```text
https://iliaeta.github.io/guap-calendar-sync/calendar.ics
```

Добавляйте её именно как календарь по URL, а не импортируйте файл один раз:

- Google Calendar: **Другие календари → Добавить по URL**;
- Apple Calendar: **Файл → Новая подписка на календарь**;
- Outlook: **Add calendar → Subscribe from web**.

Частоту фактического обновления подписки определяет сам календарный клиент; она может быть больше 30 минут.

## Настройки учебного периода

Значения по умолчанию уже выставлены для осеннего семестра 2026/27:

```dotenv
ACADEMIC_WEEK_ONE_MONDAY=2026-08-31
SEMESTER_START=2026-09-01
SEMESTER_END=2027-01-31
TIMEZONE=Europe/Moscow
```

Перед следующим семестром даты нужно обновить. Если расписание другой группы, замените `GUAP_SCHEDULE_URL`.

## Структура

- `src/download_schedule.py` — загрузка страницы;
- `src/parse_schedule.py` — парсинг и защитная валидация;
- `src/diff.py` — сравнение версий и текст уведомлений;
- `src/sync.py` — доставка в Telegram с разбиением длинных сообщений;
- `src/calendar_export.py` — генерация `.ics`;
- `src/caldav_sync.py` — двусторонняя синхронизация с Mail.ru и защита ручных изменений;
- `src/main.py` — атомарный сквозной запуск;
- `.github/workflows/sync.yml` — запуск каждые 30 минут;
- `tests/` — проверки парсера, недель, diff и календаря.
